## Part 2 — revision after reading the two documents

The files sharpen one thing and soften one thing in what I ordered this morning.

**What changes: export-first is conditional, not automatic.** The ~1 credit/MB I built that recommendation on is the trial's rate, which is the Plus rate. Dune documents Analyst at 5×. At the documented rate, pulling the full table into the repo is up to ~1,900 credits — half a month's allowance — whereas reading it in place costs 0.028 credits per full scan. So the two designs trade against each other:

* Export-first (ad-hoc chunks → repo, no view, no RW key, nothing public): simplest and most private; costs up to 1,900 on Analyst.
* In-warehouse (materialized view on Dune, H1/H2/H4 passes run as ad-hoc queries against it, only result grids exported): cheapest by far; needs the RW key, a public table, and the cron-expiry discipline. Verdicts and thresholds still never get saved — ad-hoc isn't saved, so order 6 holds either way.

Decision rule for checkout: if Analyst's export rate reads at ≤ 3 credits/MB, go export-first; if it's the documented 10, go in-warehouse, and you create the RW key then. Either way, the 85-column table is exported at most once and only the analysis columns are pulled on repeat.

**What stands: measuring the heavy tier now.** The document says phase B's 2,500–7,000 spread rests on a one-day run that cost 85 credits — and that was the buggy 4a run that returned nothing. The honest unit isn't known. Spending ~350 expiring credits to measure it on the calibration week is still the best use of the trial; ClaudeCode's day-10 plan is the fallback if the trial runs out first, not the default.

**Ratified from the documents:**

* Monthly chunks as the default build plan (the ~1,000 figure). A single 610-day pass is a hypothesis about engine limits; don't plan on it.
* Phase C (`c07b`) cut from M0; its absence recorded as biasing RUG-A recall downward, which is the safe direction.
* Day-10 kill criterion exactly as written: table built and exported for ≤ 3,000, phase B measured on one month; if B projects > 8,000, sampled window or a single Plus month becomes the comparison. No third Analyst month is bought blind.
* "Plan on the high column." Three builder estimates have run over by 3–100×; that's the right posture and I'd make it a project rule: no more than two paid months are committed before a re-ruling on measured numbers.
* The null-count-per-era validation rule for every decoded-event column. That's a durable lesson — decoded tables keep columns older layouts never filled — and belongs in principles, not just this project.

Orders unchanged from this morning except order 2, which becomes: document both designs with the checkout decision rule above, and proceed with neither until the rate is read. Orders 1, 3, 4, 5, 7 as issued.
